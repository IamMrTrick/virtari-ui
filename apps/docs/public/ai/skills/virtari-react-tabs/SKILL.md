# @virtari-packages/react-tabs

Use the existing package and its composition API. Verify the installed version against this snapshot (1.1.0); do not invent exports or Tailwind classes.

## Workflow

1. Read [API and entry points](references/api.md) for exact public names, CSS imports and source types.
2. Apply the package guidance below; use [examples](references/examples.md) for existing compositions. Examples may require their page helpers and docs scaffolding.
3. Read [design rules](references/design.md) before changing shape, spacing, surfaces, or interaction.
4. For complete repository context, use MCP `get_record` with collection `packages`, id `react-tabs`, then `read_source` for the returned source IDs. Without MCP, use the source paths in the checked-out repository.
5. Check keyboard, focus, accessible naming, disabled/error states, RTL and theme behavior applicable to the change. Preserve native form behavior and consumer event handlers.

## Integration rules

- Compose Tabs > TabsList > TabsTrigger with matching TabsContent value strings under the same root. Put variant, size, fullWidth, animatedIndicator and autoScroll on TabsList, not Tabs.
- Use value/onValueChange for controlled selection or defaultValue for the initial selected panel. Supply an accessible name for TabsList and retain trigger/content IDs and aria relationships generated by the primitive.
- The default activationMode is automatic; use manual when moving focus should not immediately activate expensive content. The primitive handles roving focus and direction-sensitive orientation keys.
- collapseAt is a container-width threshold in pixels that changes a vertical root to horizontal. Root swipeable only acts in horizontal orientation; it is separate from the carousel-style TabsPanels feature.
- Use TabsPanels with direct TabsContent children in trigger order for carousel panels. mountStrategy=all keeps every panel mounted; adjacent limits mounting to the active panel and its neighbors. touchOnly defaults true.
- Direction resolves explicit dir, DirectionProvider, then DOM inheritance. Segmented track and item/indicator radii share the system's shape roles and inset geometry; preserve data-radius-host and token-derived styles.

## Known limits and mistakes to avoid

- Tabs visually styled as pills still represent tabpanel switching, not route navigation or a form radiogroup.
- Avoid simultaneously enabling root swipeable and TabsPanels swipe handling without interaction testing; they are independent gesture implementations.
- TabsPanels relies on direct child panels and DOM relationships; arbitrary wrappers or mismatched trigger/panel order can break carousel activation.
- forceMount retains panel content beyond its active lifetime; verify focusability and screen-reader exposure in any custom offscreen animation instead of assuming mount preservation implies invisibility.
- The pill shape preset intentionally keeps many container radii finite. Uniform design language means shared semantic radius roles, not one numerical radius for every variant.

Related package IDs: `react-segmented-control`, `react-nav`, `react-scroll-area`, `primitives`, `utils`. Discover their focused skills from the catalog; do not load all packages at once.
